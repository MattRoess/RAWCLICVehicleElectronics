## 1a. THE DELIVERABLE — `Data/30_BEV_electronics_composition.csv`

**What downstream users actually want.** Same shape as a car-frame composition:
**grams per vehicle, by year, segment, domain, component type and element.**
**130,662 rows.** Tracked in git as a deliberate `.gitignore` exception, because
it is a deliverable rather than a regenerable intermediate.

```bash
.venv/bin/python tools/build_composition.py     # rebuild the file
.venv/bin/python tools/plot_composition.py      # redraw the figures
```

### Columns

| column | meaning |
|---|---|
| `Year`, `Segment` | 2020–2070; AB / CD / EF |
| `Domain` | Wiring, PCB, Sensors, Motors |
| **`Component_Type`** | **the detail for deeper work** — see below |
| `Element` | Cu, Fe, Al, Au, Nd … |
| `Mass_g_per_vehicle` | grams per vehicle, **mean** |
| `Basis` | `modelled` = the model produced that year directly; `scaled` = 2025 composition × a year-resolved driver |
| **`Histogram_File`** | **path to the probability density function** behind that series |

### Component-type resolution

| domain | types | examples |
|---|---|---|
| **Sensors** | **59** | temperature, pressure, accelerometer, air quality, ambient light, angle … |
| PCB | 18 | category × board size — `PE_HVS / medium`, `BMS / small` |
| **Wiring** | 5 | **HV Power, LV Power**, Signal/Comm, ADAS/Sensor, Specialized |
| Motors | 4 | Small/Medium stepper, MediumDC metal/plastic |

**Sensors are `modelled`, not `scaled`** — element mass per type is
`count(sensor type, year) × composition(element | sensor type)`, taking counts
from `sensor_year_stats.csv` and composition from `07_`. An earlier build said
this was not resolvable without inventing a split; **that was wrong**, and the
sensor totals changed when it was corrected (AB 196 → 113 g). Do not compare
against pre-`fe2f82c` sensor figures.

### Magnitudes, 2025 (g/vehicle) — use these to spot a broken run

| | AB | CD | EF |
|---|---|---|---|
| Motors | 23,393 | 45,573 | 95,791 |
| Wiring | 33,933 | 56,168 | 75,736 |
| PCB | 483 | 617 | 715 |
| Sensors | 113 | 168 | 212 |
| **total** | **57.9 kg** | **102.5 kg** | **172.5 kg** |

**Change to 2070: AB −13.6%, CD −10.1%, EF −0.5%** — a partial cancellation.
Wiring copper falls as zonal architecture shortens the harness; auxiliary motor
content rises with feature adoption. Small cars decline most: proportionally
larger wiring reduction, smaller motor base.

**The clearest single result**, EF wiring: **LV Power 48.4 → 35.1 kg** and
**HV Power 20.7 → 15.2 kg**, while **ADAS/Sensor wiring grows 3.2 → 4.8 kg**.
Consolidation shrinks power distribution while sensing wiring expands.

### 2a. Three aggregator bugs, and why they matter to you

`build_composition.py` ran cleanly **three times while producing nonsense**.
None crashed. Each was caught only by asking whether the number was physically
believable:

| bug | symptom |
|---|---|
| sensor summaries are in **milligrams**, read as grams | 196 **kg** of sensor material per car |
| motor `Case` encodes the segment (`EF_MediumDCMotors_metal`); averaging across cases | every segment given identical motor content, ~4× wrong AB vs EF |
| all four motor stream folders hold the **same** combined summary | every element counted 4× |

**If you extend the aggregator, sanity-check the magnitude.** That is why
`01_USER_GUIDE.md` §6 lists typical values — a run that produces 196 kg of sensors
is wrong even though nothing errored.

## 3. Driver F — why scenarios, not a wider band

**This is the most important thing to understand about today.**

The user asked whether Chinese-style EF interiors are captured. They largely were
not. The first fix was to widen the EF headroom band to `1.15/1.35/1.60`. It
passed every validation — **and it was wrong in shape.**

A band says *"the truth lies in this range"*. But whether Chinese executive
interiors become the European norm is a **structural fork**, not measurement
uncertainty. A mode of 1.35 describes **a world nobody expects** — the average of
"Europe stays European" (~1.15) and "Europe adopts Chinese content" (~1.50).

**That is exactly what `06_PCB_MODEL_DESIGN.md` §2.2d forbids for architecture:**
*share-weighting collapses a bimodal mixture into its mean and destroys the
band.* The widened band applied to motors the error the project rejects
elsewhere.

Now three coherent worlds, weights 0.40 / 0.35 / 0.25, selected via `20_`
`Control!B4` — the same cell the ADAS driver uses. **The AB > CD > EF gradient
holds inside every scenario**, not just on the mean, so M4 tests the mechanism
rather than passing by averaging.

**If you touch the motor anchors, keep this property.**

## 5. How to quote the results

**PCB:** area AB +0.4% / CD −1.1% / EF −2.0%; element mass −0.30 / −1.41 /
−1.68%. **Not a finding that material demand is flat** — it is the reach of an
8.2% driver. Always state P-g alongside.

**Motors:** counts AB +31.6% / CD +24.6% / EF +17.8%. **35 of the 50 years are
extrapolation** — every source stops at 2035.

**Everything is a scenario with uncertainty, not a prediction.**

## 6. Standing rules

- **Only the user says when work moves forward.** No modification without an
  explicit OK.
- **Investigate before correcting. Document before implementing. Keep reports in
  line with the code and the results.**
- **No dead parameters. No unsourced parameters.**
- >10× is the threshold for calling something an error.
- `ElectricMotorMC` is **auxiliary** motors, not traction.

### Traps that have each bitten once

1. **Adding a sheet can break readers** applying fixed `usecols` to every sheet
   (`01_` broke both sensor models). Check the reader first.
2. **A note in a data column changes the row count** (`Presence_per_Tier` read 13
   for 12; `BASE_YEAR` repeated it). Park notes in a far column.
3. **Non-breaking spaces in `11_` names** — exact match fails silently.
   Normalise whitespace.
4. **A cross-check that stops at the INPUT does not validate the model.** The 2×
   motor bug survived because published figures were compared against `05_`'s
   input band, not against what the model reported.
5. **Mechanisms this project already solved get rewritten from scratch** — the
   V13 rule, `shift_shares`, the accumulator. Ask "has this been solved here?"
   before designing.
